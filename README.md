# Invariance and Body-Order Compose Additively: Minimax Rates on SO(3)^n

Code, result files and figure scripts for

> Zheshuo Li and Zhengxiong Li. *Invariance and Body-Order Compose Additively: Minimax Rates on SO(3)^n.* NeurIPS 2026.

Everything in the paper's experimental sections (Section 4 and Appendices K–P) can be
regenerated from this repository. The result files that produced the camera-ready
figures are included in `results/`, so all figures and tables can be rebuilt in seconds
without rerunning the experiments.

## Layout

```
experiments/   one self-contained script per experiment (NumPy/SciPy; PyTorch for the neural bridge)
results/       the JSON files behind every figure and table in the paper
plots/         make_figures.py: rebuilds every paper figure/table from results/
figures/       output of plots/make_figures.py
```

## Installation

```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Python 3.10+; NumPy, SciPy and Matplotlib for the spectral experiments, PyTorch for the
neural bridge (CPU is sufficient; on Apple Silicon the bridge uses the MPS backend when
available). The archived results were produced on a MacBook Pro (Apple M1 Max, 64 GB)
with Python 3.11.15, NumPy 2.4.4, SciPy 1.17.1 and
PyTorch 2.11.0 (spectral experiments on CPU, neural bridge on the MPS backend).

## Rerun the experiments

Every script writes its result JSON into the current working directory, so run them from
`results/`; the paper figures are then generated by `plots/make_figures.py`. Every script
accepts `--help`.

```
cd results
python ../experiments/experiment4.py --quick     # reduced configuration to check the environment
python ../experiments/experiment4.py             # configuration used in the paper
```

`--quick` runs a reduced configuration (fewer repetitions, smaller N); it writes
`*_quick.json` and never overwrites the archived result files.

**Reproducibility.** The archived JSON files reproduce the reported figures and tables.
Rerunning the experiments uses the documented configurations and seeds (`seed_base` in
each script); numerical results may vary with the software version and computing
backend. The spectral experiments are deterministic given the seeds; for the PyTorch
experiments, bitwise agreement is only expected on the same software and hardware.

**Checkpoints.** `experiment2.py`, `neural_bridge.py` and `neural_bridge_control.py` save
a checkpoint after every completed unit of work and resume automatically when rerun with
the same command; `--fresh` ignores an existing checkpoint. The neural-network checkpoints
store the full configuration and the available torch RNG states. Exact continuation
requires successful RNG-state restoration on the same software and backend; the code warns
when this is not possible. All three scripts write checkpoints atomically and ignore a
checkpoint whose configuration differs from the current one.

## What the scripts implement

All spectral estimators are finite Wigner-D dictionaries with Sobolev-weighted coefficient
shrinkage (Appendix K.1 of the paper). The four function classes differ in the coordinate
system and the body-order of the expansion:

* `F_Kinv`: pair (and, for K = 3, pure triplet) modes in relative coordinates
  `g_i^{-1} g_j`, pulled back to SO(3)^n;
* `F_K`: pair modes in absolute coordinates on SO(3)^2 per pair (plus one-body modes);
* `F_inv`: a single expansion on SO(3)^{n-1} in relative coordinates;
* `F_0`: a single expansion on SO(3)^n.

Shrinkage parameter. All estimators use `mu = (1 + Lambda*)^(-s)` with
`Lambda* = (N/M)^(2/(2s+D))`, where `M` is the number of subsets at the given body order
(`M = C(n,2)` for pairs, `M = 1` for `F_inv` and `F_0`). The following experiments additionally divide
`mu` by `sqrt(M)` for the structured estimators: `experiment1.py` / `experiment1_s3.py`
(the `F_Kinv` pair estimator) and `k3_study.py` (each body-order level, with that level's
`M`). Experiments 2–5 (including the Experiment 5 robustness variants) use the base
shrinkage formula with class-specific `D` and `M` and no additional `1/sqrt(M)` factor.
Each script states its convention next to the estimator definitions.

Experiment 4's K' = 3 candidate applies the pure-S projection `P_Delta^perp` to the (1,1)
triplet block (72 pure modes per triplet), the projection `P_Delta^perp` of Appendix C of
the paper; the candidate family is the fixed-cutoff sample-splitting estimator of
Appendix J. The same projection is used in `k3_study.py`. In `exp4_data.json`, the key `oracle` holds the
true-order candidate (K' = 2 fit on all N); the paper's *empirical oracle* is the pointwise
minimum of the mean risks of the three fixed candidates K' = 1, 2, 3 and is computed in
`plots/make_figures.py` (and reported alongside the true-order comparison by the script).
The Maier–Saupe target of Experiment 5 is
`f*(g) = -c_n sum_{i<j} [P_2(x_ij) + 0.3 P_4(x_ij)]` with
`x_ij = (tr(g_i^{-1} g_j) - 1)/2`.
